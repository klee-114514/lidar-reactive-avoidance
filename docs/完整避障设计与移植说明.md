# 完整避障设计与移植说明

## 1. 适用范围

这是一个二维激光雷达局部反应式避障算法，不建立全局地图，也不依赖 ROS 或 SLAM。

算法适合差速轮式或能够原地转向的移动机器人。

车辆运动层至少需要支持：

- 保持指定航向行走一个测量小步；
- 原地转向指定绝对航向；
- 返回实测航向和实测行进距离；
- 提供堵转和急停状态。

如果车辆不能原地转向，需要把原地动作替换成满足最小转弯半径的轨迹。

### 雷达要求

| 条件 | 要求 |
|---|---|
| 数据 | 同时提供距离和角度 |
| 视野 | 前半球至少 180°，360° 更便于侧距和回线 |
| 周期 | 建议不大于 200 ms |
| 角度分辨率 | 建议不低于 1°，控制器最终归约为 5° 扇区 |
| 最小距离 | 小于触发距离和安全包络 |
| 最大距离 | 覆盖触发距离和前视距离 |
| 健康状态 | 能判断扫描是否持续更新 |

不要求特定品牌。

旋转式二维雷达可以直接接入。

固态雷达或三维雷达只要能转换成相同的扇区距离和侧距，也可以使用。

雷达扫描面必须能看见需要避让的障碍，并考虑低矮障碍和安装高度造成的盲区。

仓库中的 FPGA 示例固定解析 RPLIDAR A1 协议，但 C 参考控制器与雷达品牌无关。

## 2. 坐标与数据约定

控制器内部推荐使用：

- `+X` 指向车头；
- `+Y` 指向车辆左侧；
- 航向逆时针为正；
- 距离单位 mm；
- 角度单位度。

雷达点 `(距离 d，角度 θ)` 的坐标为：

```text
x_sensor = d * cos(theta)
y_sensor = d * sin(theta)
```

雷达不在后轮轴中心时，应转换到后轮轴坐标系：

```text
x_axle = x_sensor + A_sensor_axle
y_axle = y_sensor + B_sensor_vehicle
```

其中：

```text
A_sensor_axle = 后轮轴到车头距离 - 雷达中心到车头距离
B_sensor_vehicle = 雷达相对车辆纵轴的左向偏置
```

雷达在车辆左侧时 `B_sensor_vehicle` 为正，在右侧时为负。

推荐把一整圈扫描归约为 72 个 5° 扇区。

参考实现使用：

- 第 `0` 格为车头正前；
- 正角度转向车辆左侧；
- 第 `18` 格为车正左；
- 第 `54` 格为车正右；
- `0xFFFF` 表示无有效回波。

如果雷达原始角度不同，必须在适配层统一，不能把两套角度约定混进控制器。

## 3. 必须手动测量和填写的参数

| 参数 | 测量方法 | 用途 |
|---|---|---|
| `L_total` | 前后最外缘距离，含保险杠 | 后悬和车体扫掠 |
| `W_total` | 左右最外缘距离，含轮子 | 横向安全包络 |
| `A_axle_front` | 后轮接地点到车头前缘 | 障碍近面和扫掠范围 |
| `A_sensor_front` | 雷达光心到车头前缘 | 雷达坐标转换 |
| `B_sensor_center` | 雷达相对车辆纵轴偏置，左侧为正 | 雷达坐标转换 |
| `H_sensor` | 雷达扫描面离地高度 | 判断雷达能否看见障碍 |
| `R_pivot` | 原地转向时最远车角扫出的半径 | 原点转向碰撞检查 |
| `V_cruise` | 正常前进速度 | 计算触发距离 |
| `A_brake` | 实测制动减速度 | 计算制动距离 |
| `T_scan` | 一圈扫描周期 | 计算控制延迟 |
| `D_min` | 雷达最小有效距离 | 过滤自身和盲区 |

推荐派生参数：

```text
rear_overhang = max(L_total - A_axle_front, 0)
sensor_axle = A_axle_front - A_sensor_front
sweep_half_width = W_total / 2 + side_margin
target_side_clearance = W_total / 2 + side_margin

trigger_distance =
    V_cruise^2 / (2 * A_brake)
    + V_cruise * T_scan
    + sensor_margin
```

没有实测 `R_pivot` 时，可用下式做保守估计，但最终仍应实车测量：

```text
R_pivot_estimate =
    sqrt((L_total / 2)^2 + (W_total / 2)^2)
    + side_margin
```

常用初始值：

| 参数 | 建议初值 |
|---|---:|
| `side_margin` | 50~100 mm |
| `step_mm` | 40~100 mm |
| `turn_tolerance` | 3°~5° |
| `return_tolerance` | 10~20 mm |
| `front_lost_scans` | 3 圈 |
| `blocked_mm` | 比触发距离大 100~200 mm |

这些值必须通过实车测试调整，不能直接复制其他车辆参数。

可直接填写 [vehicle-calibration.csv](../config/vehicle-calibration.csv) 记录全部测量结果。

填写完成后，把 [lra_vehicle_config.example.h](../config/lra_vehicle_config.example.h) 复制为项目自己的配置文件并替换所有 `TODO_` 常量。

## 4. 平台接口

控制器每次读取一份一致的输入快照：

| 输入 | 单位 | 说明 |
|---|---:|---|
| `bins[72]` | mm | 上一圈各扇区最小距离 |
| `scan_valid` | 布尔量 | 扫描数据是否新鲜 |
| `scan_done` | 单次事件 | 是否刚完成一整圈 |
| `front_lost` | 布尔量 | 当前圈是否没有正前障碍段 |
| `front_mm` | mm | 正前净空 |
| `left_mm` | mm | 左侧垂直净空 |
| `right_mm` | mm | 右侧垂直净空 |
| `heading_deg` | 度 | 当前航向 |
| `heading_valid` | 布尔量 | 航向是否有效 |
| `travel_delta_mm` | mm | 本运动小步的实测距离 |
| `step_done` | 单次事件 | 本运动小步是否完成 |
| `stall` | 布尔量 | 电机堵转或运动无进展 |

控制器只产生三种运动请求：

| 输出 | 说明 |
|---|---|
| `STOP` | 停止并制动 |
| `HOLD_HEADING` | 保持目标航向走一个测量小步 |
| `PIVOT_TO_HEADING` | 原地转到目标绝对航向 |

输出中同时包含目标航向、步长、状态、失败原因和中止标志。

运动层必须用实测结果确认动作完成，不能只按固定时间推进。

[lidar_avoidance_adapter.h](../platform/mcu-template/lidar_avoidance_adapter.h) 和 [lidar_avoidance_adapter.c](../platform/mcu-template/lidar_avoidance_adapter.c) 提供了 MCU 胶水层模板。

移植时需要实现四个回调：

- `read_snapshot`：读取一份一致的传感器和运动状态快照；
- `apply_action`：执行保持航向小步或原地转向；
- `stop`：普通停止；
- `emergency_stop`：故障急停。

编译时把 `reference/c/` 加入头文件搜索路径，模板通过 `lidar_reactive_avoidance.h` 引用控制器接口。

## 5. 完整执行顺序

```text
扫描并检查数据
  -> 检测到障碍
  -> 选择绕行侧
  -> 检查车体扫掠
  -> 转到初始绕行航向
  -> 小步贴边跟随
  -> 判断已经越过
  -> 返回原航线
  -> 转回原航向
  -> 恢复任务
```

### 5.1 扫描与触发

每完成一整圈，原子更新一次扇区数据。

扫描超过允许时间没有更新时，立即设置 `scan_valid=0` 并停车。

链路健康时，无回波可以作为自由空间。

链路失效时，不能继续把无回波当作自由空间。

满足以下条件后进入避障：

```text
front_mm <= trigger_distance
scan_valid = true
heading_valid = true
vehicle_idle = true
```

进入时保存：

- 基准航向 `home_heading`；
- 任务剩余里程；
- 障碍近面到后轮轴的距离；
- 前进累计；
- 横向累计；
- 总路程和额外路程。

### 5.2 选择大方向

把距离小于 `blocked_mm` 的扇区标记为阻塞。

在前半球寻找连续自由扇区，并要求：

```text
free_run_width >= min_free_angle
```

候选自由段优先选择中心离正前最近的区域。

72 扇区体系可先用 8 格，即 40°。

最小自由宽度必须大于车体在对应距离上的角宽。

### 5.3 检查车体扫掠

左右两侧分别测试 `0°` 到 `max_phi`，每 5° 一档。

把障碍点转到候选航向坐标：

```text
u =  x * cos(candidate_angle) + y * sin(candidate_angle)
v = -x * sin(candidate_angle) + y * cos(candidate_angle)
```

以下情况拒绝候选角：

```text
abs(v) <= sweep_half_width
且
-rear_overhang <= u <= A_axle_front + lookahead_mm
```

同时检查原地转向圆：

```text
sqrt(x^2 + y^2) <= R_pivot
```

任意有效障碍点进入旋转圆，都不允许直接原地转。

选择左右两侧中可行且转角更小的一侧。

角度相同使用固定规则。

选出的角度建议再加 5° 量化余量。

两侧都不可行时停车并报告“无安全方向”。

### 5.4 转到初始绕行航向

目标航向：

```text
target_heading = home_heading + side_sign * phi
```

`+1` 表示左绕，`-1` 表示右绕。

转向完成后检查：

```text
abs(wrap_angle(measured_heading - target_heading))
    <= turn_tolerance
```

转向失败时有限次重试。

仍失败时，先尝试转回 `home_heading`，再报告失败。

### 5.5 小步贴边跟随

每一步完成后使用实测数据更新里程：

```text
angle_offset = wrap_angle(measured_heading - home_heading)
forward_mm  += travel_delta_mm * cos(angle_offset)
lateral_mm  += travel_delta_mm * sin(angle_offset)
```

不能使用命令航向和命令步长代替实测值。

根据障碍侧净空修正绕行角：

```text
phi =
    phi + side_gain
    * (target_side_clearance - measured_side_clearance)
phi = clamp(phi, 0, max_phi)
```

初始可令 `side_gain=0.05~0.15` 度/mm。

向左绕时读取车辆右侧净空。

向右绕时读取车辆左侧净空。

一次绕障只允许在当前侧调整，不中途翻向另一侧。

### 5.6 判断已经越过障碍

以下条件应同时成立：

```text
forward_mm >= obstacle_near_axle + pass_margin
side_clearance >= return_clearance
```

同时满足一项：

```text
front_lost_count >= front_lost_scans
或
front_mm >= resume_front_clearance
```

建议：

```text
pass_margin = rear_overhang + 20~50 mm
return_clearance = W_total / 2 + 100~200 mm
```

条件不满足时继续小步跟随。

### 5.7 返回原航线

剩余横向误差：

```text
lat_abs = abs(lateral_mm)
lookahead = max(forward_mm, lookahead_min)
```

回线角：

```text
return_angle =
    clamp(atan2(lat_abs, lookahead),
          min_return_angle,
          max_return_angle)
```

回线航向：

```text
return_heading =
    home_heading - side_sign * return_angle
```

参考 C 实现使用 30°、34°、38° 三档近似。

回线过程中不断从横向误差中扣除实测横向分量。

横向误差进入 `return_tolerance` 后结束回线。

回线路径被障碍堵住时，重新进入边界跟随。

### 5.8 最终回正与恢复

车辆最后转回 `home_heading`。

恢复任务前确认：

```text
abs(measured_heading - home_heading) <= turn_tolerance
front_mm >= resume_front_clearance
```

恢复进入避障前保存的任务剩余里程。

### 5.9 失败停车

出现以下任一情况立即停车并锁存原因：

- 扫描无效；
- 航向无效；
- 两侧都没有可行方向；
- 车体包络侵入；
- 转向连续失败；
- 电机堵转；
- 额外路程超限；
- 总时间超限；
- 恢复任务时正前仍不安全。

如果条件允许，失败前先转回 `home_heading`，避免下一条任务继承大角度偏差。

## 6. MCU 移植顺序

### 6.1 传感器适配

把雷达、IMU 和编码器转换成第 4 节定义的输入快照。

扫描数据应使用双缓冲，避免控制器读到半圈新、半圈旧的数据。

### 6.2 运动适配

`HOLD_HEADING` 至少包含：

- 航向环；
- 速度环；
- 编码器闭环；
- 实测步长完成判断。

`PIVOT_TO_HEADING` 至少包含：

- 绝对航向目标；
- 转向方向滞回；
- 到位和停稳判断；
- 超时保护。

### 6.3 控制循环

```c
while (1) {
    if (control_tick_due()) {
        lra_input_t input = read_input_snapshot();
        lra_output_t output;

        lra_update(&controller, &input, &output);

        if (output.abort) {
            emergency_stop();
        } else {
            apply_motion_request(&output);
        }
    }
}
```

参考接口：

```c
void lra_default_config(lra_config_t *config);
void lra_reset(lra_controller_t *controller,
               const lra_config_t *config);
void lra_update(lra_controller_t *controller,
                const lra_input_t *input,
                lra_output_t *output);
```

有 FPU 的 MCU 可以直接参考实现。

没有 FPU 时，使用定点角度、Q 格式三角函数和预计算正切表。

## 7. 首次标定顺序

1. 车体静止，确认雷达左右方向。
2. 确认雷达点坐标转换和正前距离基准。
3. 确认 IMU 航向正负。
4. 确认编码器前进正负。
5. 实测 90° 原地转向误差。
6. 实测 100 mm 直行误差。
7. 测量雷达最小距离和扫描高度盲区。
8. 测量不同地面的制动距离。
9. 计算并填写触发距离。
10. 测量并填写车身宽度、长度、后轴位置和雷达安装位置。
11. 测试正前方障碍、左侧偏置和右侧偏置。
12. 测试细杆、宽墙、墙角和雷达断线。

每次只修改一个参数。

## 8. 扫描回放示例

[scan-replay](../examples/scan-replay) 目录提供六组说明性扫描数据：

- 空旷区域；
- 正前方居中箱子；
- 障碍偏左；
- 障碍偏右；
- 没有安全方向；
- 回线路径重新被堵。

CSV 格式为：

```text
name=场景名称
front_mm=正前净空
left_mm=左侧净空
right_mm=右侧净空
heading_deg=当前航向
scan_valid=扫描是否有效
front_lost=正前障碍是否消失
expected_state=人工判读的预期状态
bins=72个逗号分隔距离
```

这些文件用于比较不同移植实现的行为，不是自动测试套件。

当前没有可用 MCU，也没有声明这些场景已经通过实车验证。

## 9. 验证与限制

至少验证：

| 场景 | 通过条件 |
|---|---|
| 雷达断流 | 立即停车 |
| 航向失效 | 禁止继续运动 |
| 左右对称障碍 | 得到左右镜像结果 |
| 转向 | 实测角度进入容差并停稳 |
| 编码器 | 使用实测距离判断小步完成 |
| 单圈丢点 | 不能解除避障 |
| 回线阻塞 | 重新进入跟随 |
| 包络侵入 | 立即停车 |
| 超时 | 不允许无限绕障 |

主要限制：

- 没有全局地图；
- 可能陷入凹形障碍；
- 不预测移动障碍；
- 玻璃、低反射率物体和雷达盲区可能漏检；
- IMU 和编码器会漂移；
- 参数与车辆几何和地面条件强相关；
- 不能替代硬件急停和功能安全设计。
